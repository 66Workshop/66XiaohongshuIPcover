# 生产工作流｜小红书 IP 封面 V0.1

## P0｜输入锁定

每次任务必须先锁 6 件事：

1. 主题
2. 车型/项目
3. 主钩子标题
4. 人物素材 ID
5. 车型主锚定图
6. 证据图 1–3 张

没有证据图时，宁可做观点封面，也不要凭空生成假配件。

## P1｜模板选择

按内容类型路由：

- 数据/实测 → `P01_DATA_CONFLICT`
- 修复/拆解/避坑 → `P02_BEFORE_AFTER`
- 单车型为什么改 → `P03_VEHICLE_DECISION`
- 产品/方案值不值 → `P04_PRODUCT_VALUE`

## P2｜标题生成

标题先通过人工确认，再进入图像生成。

原则：
- 一张封面只讲一个冲突
- 黑字负责事实，红字负责冲突
- 标题不负责写完整结论

## P3｜人物处理

1. 使用 approved 人物图
2. 抠绿幕/透明化
3. 不改脸
4. 只调光影/色温/接触阴影

## P4｜证据处理

- 车型：锁车身结构、灯组、轮毂、姿态
- 配件：锁颜色、外形、Logo、盘面结构
- 实测：重量、尺寸、前后对比图必须来自真实证据

## P5｜生成候选

一次建议 3–4 张：

- 70% 保守稳定版
- 20% 强钩子版
- 10% 实验版

不要一次生成 20 张再凭感觉挑，容易把错误规模化。

## P6｜QA Gate

必须逐项检查：

- 人脸
- 车型
- 配件
- 标题
- 版式
- 品牌

失败即记录原因。

## P7｜成功回写

通过的人审版本进入：

`examples/successful/`

同时更新 manifest，记录：

- 主题类型
- 使用模板
- 使用人物素材
- 标题结构
- 哪些元素被认为成功
- 哪些元素仍需优化

## P8｜失败回写

失败图不必都存原图，但必须记录失败模式：

- face_drift
- car_drift
- product_hallucination
- title_error
- layout_overload
- weak_hook
- fake_evidence

## P9｜20 任务复盘

每 20 个任务统计：

- 一次可用率
- 平均候选数
- 人脸失败率
- 车型/配件失败率
- 标题错字率
- 平均返工时间

只有数据表明稳定性上升，才升级到 V0.2。
